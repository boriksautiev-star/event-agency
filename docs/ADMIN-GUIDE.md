## Роли

| Роль | Кто | Доступ |
|------|-----|--------|
| **director** | Директор / владелец | Всё |
| **admin** | Менеджер / администратор | Заказы, клиенты, справочники, подтверждение передач |
| **animator** | Аниматор | Свои заказы, отчёты, передача, отметка выполнения |

Разные роли видят разные разделы в меню (см. скриншоты в [README](../README.md)).

## Вход в систему

**Веб-панель:**
1. Откройте URL агентства (например, `https://agency-ivanov.ru`).
2. Введите телефон и пароль.
3. Нажмите «Войти».

**Мобильное приложение:**
1. Откройте приложение.
2. Если первый раз — укажите URL сервера (см. [INSTALL.md](INSTALL.md#-шаг-6-мобильное-приложение-для-аниматоров)).
3. Введите телефон и пароль.

## Заказы

### Создание заказа

**В админке:** «Заказы» → кнопка **«+ Новый заказ»**.

**Заполнить:**
- **Клиент** — выбрать из справочника (или создать нового)
- **Название** — например, «Свадьба Ивановых»
- **Дата события** — когда проходит заказ
- **Время** — с/до (например, 14:00–18:00)
- **Адрес** — где мероприятие
- **Слоты** — персонажи + длительности + цены (можно добавить несколько)
- **Скидка** — процент (опционально)
- **Предоплата** — сумма и отметка об оплате
- **Политика транспорта** — кто платит за такси

После заполнения — **«Создать»**.

### Статусы заказа

| Статус | Значение | Допустимые переходы |
|--------|----------|---------------------|
| `new` | Новый | → `confirmed`, `in_progress`, `cancelled` |
| `confirmed` | Подтверждён | → `in_progress`, `cancelled` |
| `in_progress` | В работе | → `completed`, `cancelled` |
| `completed` | Выполнен | (конечный) |
| `cancelled` | Отменён | (конечный) |

> ⚠️ Система **блокирует** недопустимые переходы. Например, `new → completed` — нельзя, нужно сначала `confirmed`.

**Кто может менять:**
- `director` — любой переход
- `admin` — любой, кроме `→ completed` (это подтверждает директор или аниматор)
- `animator` — только «Выполнен» для своих заказов (через кнопку «Отметить выполненным»)

### Назначение аниматора

1. Откройте заказ → в блоке «Персонажи и программа» найдите слот.
2. Нажмите на слот → «Назначить аниматора».
3. Выберите из списка свободных аниматоров (система не покажет занятых).
4. Нажмите «Назначить».

Аниматор получит push-уведомление. Он может принять или отклонить заказ.

## Аниматоры и ставки

### Добавление аниматора

**Только директор:** «Сотрудники» → «+ Добавить сотрудника».

**Заполнить:**
- Имя, фамилия
- Телефон (для входа)
- Пароль (минимум 8 символов)
- Роль: `animator` / `admin` / `director`

### Шаблоны ставок

**«Аниматоры» → таб «Шаблоны ставок».**

Шаблон — это таблица «группа персонажей × длительность → сумма выплаты аниматору».

**Создать шаблон:**
1. «+ Новый шаблон» → введите название (например, «Стандартный 2026»).
2. В таблице заполните суммы по строкам (группы) и столбцам (длительности).
3. Нажмите «Сохранить».

**Привязать шаблон к аниматору:**
1. В списке аниматоров нажмите на **Layers** (кнопка рядом с аниматором).
2. В секции «Шаблон» выберите из dropdown → «Сохранить».

При назначении аниматора на заказ — payout автоматически подставится из его шаблона.

### Персональные override

Если аниматору платят больше/меньше за конкретного персонажа — задайте **override**:

1. Layers → «Переопределения».
2. В таблице «персонаж × длительность» заполните значение (пусто = использовать шаблон).
3. «Сохранить».

**Приоритет:** override → шаблон → ручной payout.

### Кастомные длительности

В карточке персонажа: «+ Добавить длительность» → стандартные чипсы (30, 40, 45, 60, 90, 120, 180) + своя (1–1440 мин).

Длительность автоматически попадает в шаблоны и override как новый столбец.

## Передача заказов

Аниматор не может выполнить заказ (заболел, форс-мажор) → передаёт другому аниматору.

### Как передать (аниматор)

1. Откройте заказ → «🔄 Передать заказ».
2. Выберите получателя из списка (только свободные в этот день).
3. Добавьте комментарий (например, «Заболел, прошу заменить»).
4. Отправьте — получателю придёт push.

**Отозвать** переданный заказ можно через «Мои передачи» (до того, как получатель согласился).

### Как получить (аниматор)

1. Push-уведомление «Запрос на передачу».
2. «Профиль» → «Входящие передачи» → открыть заявку.
3. **«Принять»** — заказ перейдёт на вас **после** подтверждения админом.
4. **«Отклонить»** — укажите причину.

### Как подтвердить (админ/директор)

1. Push «Передача ждёт подтверждения» (или баннер на Сводке).
2. «Передачи» → «Ожидают» → открыть заявку.
3. **«Подтвердить»** — аниматор заменяется:
   - Старый аниматор → `removed` (причина `handed_over`)
   - Новый аниматор → `invited` (payout из шаблона/override)
4. **«Отклонить»** — с комментарием (push обоим).

**Пока админ не подтвердил — заказ остаётся у старого аниматора.**

## Финансы

### Предоплата и финальный расчёт

В карточке заказа:
- **Сумма предоплаты** — только директор
- **Отметка «оплачено»** — директор + админ
- **Финальный расчёт** — все (включая аниматора — для отметки получения на месте)

**Способы оплаты:**
- Наличные
- Перевод

Сдача в кассу / сверка — только директор.

### Выплаты аниматорам

**«Финансы» → «Выплаты аниматорам»:**
- Показывает: кому сколько причитается за период
- Отметить «выплачено» (нал/перевод)
- Автоматически учитывается в отчёте по аниматору

### Расходы

**«Финансы» → «Расходы»:**
- Категории: транспорт, реквизит, реклама, прочее
- Добавить: дата, категория, сумма, комментарий

### Касса за месяц

На «Сводке» директора — виджет «Касса за месяц»: сколько пришло, сколько ушло, остаток.

## Отчёты

### Отчёт по аниматору

**«Аниматоры» → выбрать аниматора → «Отчёт».**

**Что внутри:**
- **Сводка:** заказов, часов, начислено, выплачено, к выплате, процент принятия
- **Разбивка по причинам:** отказы, передачи, снятие (ротация/качество), отмена
- **Передачи заказов:** передал N, получил M, среднее время до approve + история
- **История расставаний:** все отказы/снятия с комментариями
- **Отработанные заказы:** список с деталями

**Фильтры:** период (месяц, прошлый месяц, год, свой), scope (все, прошедшие, будущие).

### Сводка директора

**Главная страница после входа.**

- **4 метрики:** заказов сегодня / свободные аниматоры / без аниматора / без предоплаты
- **Касса за месяц** (график)
- **Ближайшие заказы** (3 дня)
- **Требуют назначения** — заказы без аниматора
- **Ожидают предоплату** — заказы без отметки об оплате
- **Баннер «Передачи (N)»** — если есть заявки на approve

## Бэкапы

### Автоматические

Каждый день в **03:00** — автоматический бэкап БД.

- Хранится в `C:\EventAgency\server\backups\`
- Ротация: 30 дней
- Формат: `event_agency_YYYY-MM-DD_HH-mm-ss.dump`

**Если бэкап не выполнится 25+ часов** — директору придёт push «⚠️ Бэкап БД не выполнен».

### Ручной бэкап

**Из админки:** Настройки → Резервные копии → «Создать бэкап сейчас».

**Из PowerShell:**

```powershell
cd C:\EventAgency\server
npm run db:backup
```

### Где хранить бэкапы (настройка)

**Настройки → Место хранения бэкапов:**

**Локально (обязательно):**
- По умолчанию `C:\EventAgency\server\backups\`
- Можно изменить (например, на сетевую папку `\\nas\backups`)
- Кнопка «Обзор…» — выбор папки через проводник

**S3-облако (опционально, N таргетов):**
- Поддерживаются: Yandex Object Storage, VK Cloud, AWS S3, Selectel, MinIO, Backblaze B2
- После локального бэкапа файл автоматически загружается в облако
- Секретные ключи (secretKey) шифруются AES-256-GCM
- Кнопка «Проверить подключение» — тестовая загрузка

### Восстановление

**Настройки → Резервные копии → выбрать бэкап → «Восстановить».**

1. Введите **пароль директора** для подтверждения.
2. Система **создаст safety-бэкап** текущей БД (на случай ошибки).
3. Появится **готовая команда** для сервера: скопируйте её.
4. На сервере в PowerShell выполните эту команду.
5. Скрипт остановит API → восстановит БД → применит миграции → запустит API.

> ⚠️ Восстановление **перезапишет все текущие данные**. Используйте только в крайнем случае.

## Уведомления

**Настройки → Уведомления (push):**

Тумблеры по событиям:
- Аниматор завершил работу (нужно закрыть заказ)
- Аниматор ответил на назначение (принял/отклонил)
- Передача заказа ждёт вашего подтверждения
- Бэкап БД не выполнен

Отключите ненужные — push перестанут приходить.

**Мобильное приложение:** Профиль → Настройки уведомлений.

## Лицензия

**Настройки → Лицензия:**

- Показать: агентство, дата окончания, дней осталось, статус
- **«Загрузить новый файл (.key)»** — выбрать `license.key` → загрузится

**Статусы:**
- `Активна` — всё работает
- `⚠️ Истекает через N дн.` — жёлтый баннер в админке
- `⏳ Grace period (N дн.)` — красный баннер, но всё работает
- `❌ Истекла` — создание заказов блокируется, чтение доступно

**Продление:** получите новый `license.key` от разработчика и загрузите через UI.

## 🎓 Полезные советы

1. **Регулярно проверяйте бэкапы** — Настройки → Резервные копии → «Свежий» ли статус
2. **Не откладывайте продление лицензии** — за 30 дней придёт предупреждение
3. **Настраивайте push** — отключите шумные события, оставьте важные
4. **Для смены сервера в мобилке** — Профиль → «🔧 Сменить сервер»
5. **После обновления** — проверьте, что служба запустилась (`nssm status EventAgencyAPI`)

---

## 🆘 Если что-то не работает

**Заказ не назначается на аниматора** — проверьте, что у аниматора нет заказа в это время.

**Push не приходят** — настройки уведомлений + проверка, что APK установлен с Google Play Services.

**Бэкап не выполняется** — проверьте Task Scheduler: `Get-ScheduledTask -TaskName "EventAgency-DB-Backup"`.

**Другие проблемы** — см. [INSTALL.md → Решение проблем](INSTALL.md#-решение-проблем).
